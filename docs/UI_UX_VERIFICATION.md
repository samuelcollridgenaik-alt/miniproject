## Manual interaction and visual review

Keyboard checks covered dialog focus wrap/Escape/trigger restoration, flashcard Enter, avoiding global shortcut interception in search, radio arrow navigation, settings cancellation, registration validity, and the compact timer through sidebar collapse. Existing sidebar resizing/collapse and chat draft semantics retain their earlier checks and unit coverage; they were not retested exhaustively with every input method in this audit.

The screenshot review includes desktop/mobile cards, quiz, analytics, account registration, settings and evaluator surfaces, with the complete catalogue available for review. Matrices measure layout states; snapshots alone are not counted as functional success.

The final clean browser tab reported no JavaScript console errors. Gemini Lite could be selected and restored, the skip link focused `workspace-main`, and the final evaluator rerun reported 5 passed/0 failed.

The real TXT upload initially remained in processing for an extended period but ultimately indexed successfully. Upload/paste/removal requests now use a bounded API helper. Browser timeout does not cancel work already executing on the server, so the UI advises refreshing the library before retrying.

## Data and environment notes

Two clearly named temporary audit documents were created for real upload/paste checks, then removed using their exact IDs/fixture names. The original MCA document remains. No test quiz scores were inserted into learning analytics. The existing evaluator backend unit suite writes a study plan through its planner service; browser planner checks also persisted generated schedules through the existing workflow. No original plans/attempts were removed or migrated. Study digest generation used the existing service and may retain its generated material.

Gemini/Groq are unconfigured in this local environment. Fallback request handling is not proof that either external provider succeeded. The alternate FastAPI service and hosted deployment were not run. No physical device, software keyboard, dedicated screen reader or full automated accessibility scanner was used. Legacy native conversation prompt acceptance and affirmative GUI document deletion were deliberately not exercised.

## Production blockers

The existing demo authentication/identity/credential storage architecture and client-trusted quiz answer keys still require backend hardening. Built-in academic templates and citation claims are not independently validated; the UI does not claim they are live independent audits. Browser-local conversation storage is not synchronized server storage or an encrypted multi-user security boundary. These issues are not concealed by a successful frontend build. Read [UI_UX_AUDIT.md](UI_UX_AUDIT.md) before public deployment.

## Local execution

Use the existing Node.js 22.12+ workflow:

```powershell
npm ci
# Preserve an existing .env; create one only if it is absent.
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm run dev
```

Open http://localhost:3000. API-backed features need the Express dev server; `npm run preview` only previews built frontend files. `npm run build` regenerates `dist/` and `api/index.js`; it does not publish a deployment. Client and backend updates should be released together. New plans use corrected calculations; regenerate older plans rather than assuming stored plans were rewritten.
